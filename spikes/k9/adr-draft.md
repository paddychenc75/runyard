# 00NN. 移到废纸篓和回收站：macOS 用 rename 加系统小工具，Windows 用随包小工具加预检

状态：提议

日期：2026-10-12

来源：技术设计 §7.1“trash”一行、§7.2 第 6、7 行、§12 第 16 项、§4.3；技术验证 K9a、K9b（`spikes/k9/README.md`）

## 背景

命令行和管理进程是不带原生模块的 Node，`runyard rm` 和自动清理（PRD #prd-auto-clean）都要求“只进废纸篓或回收站，绝不永久删除”（PRD #prd-retention）。设计原先假设：macOS 上 `rename` 进 `~/.Trash`；Windows 上用 PowerShell 的 `FileSystem.DeleteDirectory(..., SendToRecycleBin)`。K9 用真实实验检验了这两条。

实验给出的事实（数字见 README）：

- macOS：普通 Node 进程对 `~/.Trash` 可以 `mkdir` 和 `rename` 进去，不弹任何框；但不能列目录（`EPERM`），文件夹正在使用也不影响。`rename` 不写“放回原处”所需的记录，系统自带的 `/usr/bin/trash`（macOS 15 起）和 `FileManager.trashItem` 会写，三万个文件同样是毫秒级。
- macOS：对同名空目录 `rename` 会静默覆盖，不会报 `EEXIST`。
- Windows：外壳的“移到回收站”在三种情况下会静默永久删除，且没有任何标志组合能让它改为失败：路径超过阈值、目录超过回收站容量、用户设置了“删除时不移到回收站”。不带“不要确认”标志时则会弹窗，无界面环境下卡住。
- Windows：三万个文件进回收站约 10 秒，贴着 10 秒的线。

## 决定

1. macOS 的 `trash`：默认用 `/usr/bin/trash`（存在时，macOS 15 起）；没有时用 `rename` 进 `~/.Trash`（同卷）或 `<卷>/.Trashes/<uid>`（别的卷）。`rename` 之前先 `mkdir` 同名目录占位（文件用 `open(wx)`），`EEXIST` 时加时间后缀重试，不列目录。接受“没有放回原处”的损失，不用 `osascript`。随包带 Swift 小工具列为备选，不是第一版必需。
2. 跨卷且目标卷没有可用的废纸篓目录时，复制到 `~/.Trash` 再删原件；先复制到临时名，完整后才删原件，失败时原件原样保留。
3. Windows 的 `trash`：随包带一个小的 `IFileOperation` 可执行文件（可与计划中的 `runyard-job.exe` 合并），标志用“允许撤销、不确认、静默、不弹错误框、回收优先”。不用 PowerShell 方案（启动约 0.2 到 0.3 秒、路径限制更紧）。
4. Windows 的“绝不静默永久删除”由预检保证，不由标志保证：调用前遍历目录，任一路径长度超过阈值、总大小超过该卷回收站容量、卷设置了“不移到回收站”或有对应策略时，一律拒绝并返回明确的错误码，由上层决定（见 §12 第 16 项：依赖目录可直接删除，其余拒绝）。
5. 改名失败识别为 `PATH_LOCKED`：`EBUSY`、`EPERM`、`EACCES` 都按“被占用”处理；用读进程当前目录和命令行路径的小工具找出占用者，不依赖 Restart Manager。

## 后果

- 技术设计 §7.1 的 macOS 一行要加“先占位再改名”和“`/usr/bin/trash` 优先”；§7.2 第 7 行要写明预检和三种静默永久删除的情形；§4.3 释放顺序不需要改，但 `playground.released` 之后的改名可以不加重试等待。
- Windows 需要随包一个小的可执行文件和对它的签名、安全软件误报的处理，进入 M1 之前要在真机上复核。
- 预检的阈值要有测量支撑，且阈值与“用户不会遇到”之间有缺口（路径长度的边界在 520 到 600 之间未测准），所以取保守值。
- 自动清理的所有路径都经过这一层，没有任何一条能退到 `fs.rm`。

## 被否的方案

- 在 macOS 上用 `osascript` 调 Finder：需要“自动化”权限，会弹窗；实验里它在运行器上没有弹窗，但那是预先授权的环境，不能当作用户机器的证据。
- 在 Windows 上靠标志位让外壳“失败而不是永久删除”：实验里所有组合要么永久删除，要么弹窗卡住。
- 直接用 npm 的 `trash` 包：它在 macOS 和 Windows 上也是随包的预编译小工具，行为与自带小工具一致，但同样没有预检；不比自己带小工具更省事，还多一串依赖。
