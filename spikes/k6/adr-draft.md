# NNNN. 图形应用通过登录 shell 获取用户的工具链环境（macOS）

状态：提议中

日期：2026-10-12

来源：技术设计 §4.8、§7.1、§11.1 K6；`spikes/k6/README.md`

## 背景

从 Finder/Dock 启动的应用没有终端的环境变量，找不到 nvm、fnm、Volta、mise、asdf、pyenv、Homebrew 提供的工具。技术验证 K6 用真实 zsh、15 个合成环境、macos-26 上的真实版本管理器和 21 种杂乱的启动文件，验证了"向用户的登录 shell 要一次环境"可行。

## 决定

macOS 上由 `platform.env.load` 向登录 shell 要环境：用 `getpwuid` 找登录 shell；以登录加交互方式运行，在随机标记之间用 `env -0` 打印环境；stdin 为空，自成进程组，10 秒超时；看到结束标记即结束进程组。依次尝试：命令放 `-c`；命令写 stdin（穿过 rc 里的 `exec`）；只用内建打印 `PATH`；非交互登录（标记为降级）。命令里先预热懒加载的工具、再手动跑 precmd 钩子。结果按"登录 shell + 启动文件 mtime"缓存，1 小时 TTL，启动和"重新检测"时后台刷新，界面不等待。检测命令以项目目录为 cwd；项目里有版本文件时，以项目目录再捕获一次。全部失败时回退到扫描常见目录并提示。

## 后果

- 2 秒只是典型值（实测本机中位数 985 ms），不是保证；界面必须在后台解析时可用。
- 检测脚本按工具定义（Go 用 `go version`）；`env.load` 返回来源（登录 shell、降级、仅 PATH、回退）。
- 新增提示码 `ENV_UNRESOLVED`、`ENV_DEGRADED`。
- 不为每个版本管理器写专门逻辑；fish 与 bash 用同一条命令。
- 不能解析的 shell（nu、tcsh 等）直接走回退，需要"指定路径…"。

## 被否的方案

- 只扫常见目录：与完整解析一致率仅 61%（本机）、68%（CI），nvm 会选错版本，拿不到 mise activate。
- 非交互登录 shell（不加 `-i`）：读不到 `.zshrc`，124 对里少 10 对。
- 每个管理器单独适配：维护成本高，实测不需要。
