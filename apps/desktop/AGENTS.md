# @runyard/desktop（桌面应用）

## 用途

桌面应用（技术设计 §2.2、§6）。界面是 React（用 `@runyard/ui`、`@runyard/i18n/react`、`@runyard/tokens`），主窗口有外壳（设计稿 Main）：左边悬浮的玻璃侧栏（`TitleBar`、`NavList`），顶上的标签条（资源库固定在第一位、不能关闭），主题（浅色、深色、跟随系统）和语言（中文系统用简体中文，其余英文）。资源库标签的内容区是资源库页（#169，设计稿 Main、MainNarrow、Empty）：页标题和概况、项目表（`LibraryPage`、`LibraryTable`，用 `DataTable`：名称与备注、状态、模板、端口、保留、上次打开、创建者；运行中的排最前，主进程在 `build-library-state.ts` 里排好），没有项目时是空状态。表随管理进程的 `run`、`playground` 事件实时更新（控制器重读），相对时间和“剩 N 天”每半分钟走字。顶栏有“N 个运行中”（标签页和命令行持有的都算）。操作列是 `RowActions`（#171）：已停止的行主操作“打开”（`tab.open`，打开即运行，双击行同），运行中的是“停止运行”（`run.stop`），后面的更多菜单（`Menu`，网页层，打开期间 `useOverlay` 让预览让位）按设计稿 RowMenu 的顺序和分隔线排满（#290、#183，规格 DESKTOP-LIBRARY-VIEW-31 至 33、43 至 48）：打开（右侧“回车”）、打开但不运行（`tab.openWithoutRun`，已停止的只开标签页、不启动、不算一次使用，运行中的同“打开”）、停止运行（仅运行中的行）；重命名…、编辑备注…、自动清理…（右侧“现在：…”）；另存为模板…（#292，模板页与另存弹窗见 `src/renderer/app/templates/AGENTS.md`）、创建副本；在外部编辑器中打开（`playground.openInEditor`，用设置里的编辑器）、在访达中显示、在终端中打开（`playground.openTerminal`，主进程 `integration/system-actions.ts` 里 `open -a Terminal <文件夹>`，只发请求）、复制路径、复制链接（`clipboard.copy` 写 `runyard://open/<名称>`）；移到废纸篓（警示色）。找不到文件夹的行只有重新定位…（`playground.relocate`，主进程弹文件夹选择器）、从资源库移除（`playground.forget`，不动磁盘）、复制路径；重新定位对不上时的专门说明和行下方的说明条随 #185。工作区运行条的“更多”菜单（`RunBarMenu`）是同一份项（没有“打开”那一组）；两处共用 `use-project-menu.tsx`（建在 `usePlaygroundEdits` 之上），所以同名项行为一致。移到废纸篓：`TrashConfirmDialog`（设计稿 DeleteConfirm，`ConfirmDialog` 的 `tone="danger"`）确认后调 `playground.trash`，主进程 `PlaygroundEdits.trash` 先关项目标签页、再经 `PlaygroundEdits.onReleaseWatchers` 放掉编辑器文件服务的监听（`main/index.ts` 接线）、最后交给管理进程（它先停止运行、走释放顺序、只经平台层移动）；放不进废纸篓或被占用时失败原样交回，界面用 `ActionFailedDialog` 写明原因，项目留在列表里，从不永久删除。M3 的终端接上后“关闭终端”也要在这个顺序里加上（#265）。新建入口有三处，都走模板选择器和新建弹窗（#172、#173）：顶栏右端的“新建”、空状态里的蓝色“新建项目”、空状态里三个常用模板胶囊（直接进新建弹窗）；开发期的“用内置模板新建”按钮行已经去掉。设置页（#188，规格 desktop/settings，设计稿 Settings）：侧栏“设置”是主窗口里的一页（`AppShell` 的 `page` 状态，没有顶栏；换了活动标签就回到资源库）。`renderer/app/settings/`：`SettingsPage` 排两列五组，`SettingsGroup`、`SettingsRow`、`SettingsNote`、`SettingSwitch`（比对话框里的开关小一圈，设计稿 34 × 20）、`Segments`（12 号字的分段选择）；这一期有“通用”（资源库位置带隐私警告和“旧位置的项目留在原处”确认、外部编辑器下拉、语言、主题、自动检查更新）和“编辑与运行”（自动保存三档、脚本保存后自动运行、关闭前询问、命令行空闲停止 15 分钟、30 分钟、2 小时、一行说明）以及“命令行与智能体”里的“内置模板免确认”；“依赖与网络”“运行环境”只画组名加一行“随 #189”，“命令行与智能体”其余项一行“随 #195”。设置经 `bridge/use-settings.ts` 读写（`settings.get|set`，主进程 `SettingsController` 校验后转给管理进程，并发 `settings.changed`；命令行改了设置也会推来）；语言和主题由 `App` 交给 `AppFrame`，立即生效，不重启（主进程这边：主题改 `nativeTheme.themeSource`，语言重建应用菜单并让资源库按新语言取模板名）。设置里没写语言时用启动参数或系统语言；设置里主题是“跟随系统”时 `--theme` 才生效（开发用）。主进程的系统动作在 `integration/settings-host.ts`、`external-editors.ts`（认 VS Code、Cursor、Zed、Sublime Text、WebStorm）、`privacy-folders.ts`（“桌面”“文档”“下载”）。搜索与筛选（#181，规格 DESKTOP-LIBRARY-VIEW-13 至 27）：状态在 `AppShell`（`LibraryQuery`：搜索文字、侧栏固定筛选、类型、状态、排序），纯逻辑在 `renderer/library-query.ts`（搜索名称、备注、模板；类型按模板分类；状态分运行中、已停止、有问题；运行中的无论怎么排都在最前；侧栏计数）；顶栏的 `SearchBox`（⌘F 由 `AppShell` 在资源库页监听）、页头的三个 `FilterMenu`、没有结果时的 `NoResults`（搜索文字是合法且没被占用的名字才有“新建项目，名称用…”，经 `pendingName` 预填新建弹窗）；侧栏“长期未使用”“模板”“设置”仍点不了。页概况带“存放在 …”。打开项目 = 新开它的标签页并启动运行（`run.start`，持有者是标签页、绑定到本连接）；已开着的只切换、不再启动（规格 DESKTOP-WORKSPACE-01、02）。标签页的内容区上面一行是左边的 `TabContent`（现在是文件树 `app/file-tree/FileTree`，#258：列出项目文件、隐藏 `.runyard` 和 `.git`、`node_modules` 折叠且展开才读、`files.changed` 后 60 毫秒内重读受影响的文件夹；行内新建、重命名，移到废纸篓不确认只出“已移到废纸篓”；方向键、回车、F2、⌘⌫、菜单键；与编辑器的接缝是 `WorkspaceFilesContext` 加 `FileTree` 的 `hooks`，`use-workspace-files.ts` 是 #259 之前的最小占位；拖动移动不做）和右边的 `PreviewPane`（地址栏加预览占位区；项目没在运行时占位区是“已停止”画面 `PreviewStopped`，带“运行”按钮）；脚本项目（`kind` 为 `oneshot`）没有预览，右边是 `ScriptOutput`（状态“运行中 · 已 N 秒”“已结束 · 退出码 · 耗时”、停止/运行按钮、输出）；下面是整宽的底部面板 `ConsolePanel`（脚本项目也有，设计稿 Script：输出在右边，底部是“输出 / 终端”两页）。顶栏右侧是运行条 `RunBar`（项目名、模板、状态、端口、“关闭标签页即停止”、停止/运行，状态文字的判断在 `run-view.ts`）：手动停止后标签仍开着，出现“运行”按钮再次启动，持有者仍是这个标签页（DESKTOP-WORKSPACE-11、12）。控制台：主进程的 `console-logs.ts` 对每个打开的标签页用 `logs.follow` 订阅、事件只当信号并按游标 `logs.read`（读取时已清洗，同命令行的 `logs --follow`），行留在主进程（最多 5000 显示、不翻译，管理进程插入的提示按提示码翻译。标签条里项目标签名字前的小圆点反映运行状态；项目标签有关闭钮和 ⌘W，关闭运行中的标签前出确认（设计稿 CloseConfirm，规格 DESKTOP-WORKSPACE-04 至 10，见下面“关闭标签页”）。启动进度见下面“启动进度”（#177）；失败画面（#178）见下面“失败状态的画面”。底部面板 `ConsolePanel` 是“输出 / 终端”分段切换（默认“输出”，点“终端”才创建项目的终端，界面在 `renderer/features/terminal/`，说明见 `src/main/terminal/AGENTS.md` 的“界面部分”）。版面（#309，规格 DESKTOP-LIBRARY-VIEW-61 至 64、DESKTOP-WORKSPACE-55 至 61）：资源库侧栏可收起（顶栏按钮 `PaneToggleButton` 和应用菜单的“切换侧栏” ⌃⌘S，经 `sidebar.toggle` 事件通知界面），项目标签页不显示侧栏，点侧栏任何一项都先回到资源库标签（`sidebar-navigation.ts`）；项目标签页的 `WorkspaceLayout` 里文件树、编辑器、预览（脚本是输出）和底部输出面板之间是可拖的分隔条 `ResizeHandle`（双击或回车恢复默认，方向键微调），尺寸范围和夹紧在 `shared/pane-sizes.ts`，收起状态和尺寸记在 `renderer/shared/layout-prefs.ts`（浏览器存储，失败就用默认值）；原生预览视图靠 `PreviewSlot` 的 ResizeObserver 逐帧跟随占位区，拖动时不隐藏视图。

项目标签页的编辑器（#259，规格 desktop/editor「文件标签」）在 `renderer/features/editor/`：`EditorSession`（`editor-session.ts`）是一个项目的编辑会话——打开的文件标签、选中哪个、保存、关闭前的询问、恢复上次的文件标签（`local-open-files-memory.ts` 按项目 id `renderer/shared/workspace-files.tsx` 把 `openFile(相对路径)` 交给文件树（#258，文件树不导入编辑器模块）；`EditorColumn` 是设计稿 WebLight、Script 里的编辑器卡片。⌘S 和 ⌘W 在窗口层面（捕获阶段）接：⌘W 秒后”）（`delay`，`AUTOSAVE_DELAY_MS`，每个文件各自计时，`path-timers.ts`）；`blur` 档由 `select()`（切文件标签）和 `blur()`（`EditorColumn` 监听编辑区 focusout 与窗口 blur）触发；`off` 档只有 `save()`（⌘S，任何档都立即写）。会话经 `SessionFiles.watch`（`renderer/shared/project-watch.ts`，文件树与会话共用主进程那份不计数的监听，界面一侧数着，最后一个用完才 `files.unwatch`）收 `files.changed`：`self` 的变化不理；其余读磁盘后按 `disk-change.ts` 判——没有未保存修改直接换内容（`monaco-host` `quit-flush-gate.ts`：`before-quit` 先发事件 `app.quitRequested`，界面回 `app.quitReply`（`ack` 之后不设时限，`proceed` / `cancel`），3 秒没有 ack 就放行，选取消则不 `session.bye`（运行不停）。换行不统一的提示（`mixedEol`）保存一次后清掉。接缝（后续 issue 往这里接）：智能提示（#261，DESKTOP-EDITOR-40 到 46）：`monaco-host.ts` 只给打开的文件建模型，没打开的 TS、JS 脚本由 `typescript-project.ts` 登记成 extra lib（来源是 `project-source.ts`，经 `files.list`、`files.read`、`files.changed`；跳过 node_modules、.git、.runyard、dist，单文件超 512 KB 不登记，最多 3000 个），语义诊断由 `typescript-diagnostics.ts` 自己取（Monaco 自带的只在本文件内容变了时重做，所以关掉），项目里任何变化后重问所有打开的文件；跳转到定义经 `registerEditorOpener` 打开目标文件的标签；改名改到没打开的文件时 `EditorSession.adoptEdit` 为它开标签并按用户编辑保存。语言服务按“路径加版本号”缓存，同一路径的 extra lib 与模型（或关掉又重开的模型）撞版本号会拿到旧类型，所以新模型的版本号一律抬到用过的最大值之上。测试里的真 TS 线程见 `test-support/monaco-test-workers.ts`（把 ts.worker 打成 CommonJS 放进 node 线程）。实时结果（#262）由磁盘变化驱动，不经这里。Monaco 的中文文字包是单独的 `editor/nls-zh-cn.js`，中文界面先于编辑器脚本加载。设计稿的代码配色来自 `@runyard/tokens` 的 `shikiThemes`，`editor/runtime.ts` 在不引入新颜色的前提下把 CSS 属性名、HTML 属性名、Markdown、JSON 键归到已有的颜色上。 命令面板（⌘⇧P、F1）和快速打开（⌘P）是同一个浮层（#264，规格 DESKTOP-EDITOR-57 至 74）：`renderer/features/palette/`（`PaletteHost` 管开合、焦点的去与回、按键和 `palette.open` 事件，`Palette` 只画，`palette-model.ts` 排行，`fuzzy.ts` 模糊匹配，`use-project-files.ts` 用 `files.listAll` 加监听保持文件清单最新）。命令的标识符、分组、快捷键只在 `shared/commands.ts` 登记一份，菜单（`main/native-ui/app-menu.ts`）和面板共用；命令“此刻能不能用”由各部件显示期间经 `renderer/shared/command-host.tsx` 的 `useCommands` 登记，没登记就不出现（顶栏、运行条、预览、控制台、编辑器列各管自己的）；名称在 `command-titles.ts` 走文案包。新加命令：登记表加一行、`command-titles.ts` 和两份文案加名称、在管着它的部件里 `useCommands`。“显示终端”只有登记、没有执行方，随 #263；“另存为模板…”随 #292。⌘⇧P、F1、⌘P 在主进程是菜单项（预览里也有效，⌘P 在资源库页灰掉），在界面里还有窗口层面的捕获监听抢在编辑器前面；快速打开的清单不含的目录与文件监听共用 `shared/project-ignore.ts`。

包是 `private`，没有发布配置。构建用 esbuild 自己打包（`build.ts`，产物在 `dist/`），不用 electron-vite：它要 Vite 7，而 Vite 7.3.7 发布不满 14 天（`docs/architecture/dependencies.md`）。

## 对外暴露什么

不是库。对使用者暴露的是启动方式，在仓库根目录运行：

```sh
pnpm dev                                         # 默认用真实的 ~/Runyard
pnpm dev -- --root "$(mktemp -d /tmp/ry.XXXX)"   # 试验时用临时目录，不碰 ~/Runyard
pnpm --filter @runyard/desktop smoke             # 冒烟自检：窗口不显示，新建、运行、预览、停止，成功退出码 0
```

- `--root <目录>` 或 `RUNYARD_ROOT`：代替主目录（状态目录 `<目录>/.runyard`，资源库 `<目录>/Runyard`），与命令行的 `--root` 一致；路径要短（macOS 的 socket 路径上限 104 字节）。
- `--lang en|zh-CN` 或 `RUNYARD_LANG`：界面语言；缺省看系统语言（中文系统用中文，其余英文）。
- `--theme system|light|dark` 或 `RUNYARD_THEME`：窗口明暗；缺省跟随系统。主进程据此设 `nativeTheme.themeSource`，预加载脚本在页面脚本之前写 `<html data-theme>`；设置页里的切换随后续 PR。
- 第一次运行会下载 Electron 的二进制（约 100 MB）。
- 界面拿到的唯一接口是预加载脚本交出的 `window.runyard`（`src/shared/desktop-bridge.ts`），只有三样：同步的 `bootstrap`（平台、窗口按钮位置、语言、主题等，技术设计 §6.7）、`call(方法名, 参数)`、`on(事件名, 监听)`。方法和事件是白名单（`library.get`、`run.start`、`run.stop`、`tab.open`、`tab.select`、`playground.create`、`playground.reveal`、`playground.copyPath`、`preview.*`、`console.get`、`clipboard.copy`、`link.open`、`files.*`（见下面“文件服务”）；事件 `library.changed`、`picker.open`、`console.appended`、`files.changed`），表外的名字预加载脚本和主进程都拒绝；动作失败不抛，折进状态里的 `error`（代码加参数）。预加载脚本在页面脚本运行前把 `data-platform`、`data-theme`、`lang` 写到 `<html>`。

## 本包特有的规则

- 只有本包可以导入 `electron`（技术设计 §3.2 规则 1）。界面（`src/renderer/`）没有 Node 接口，也不许导入 `electron`、`client`、`platform`、`core`、`supervisor`；预加载脚本只转发。由 Biome 的 `noRestrictedImports`、`noNodejsModules` 和界面单独的 `tsconfig.renderer.json`（DOM、没有 Node 类型）拦住。可导入的包的唯一出处是 `tooling/checks/layers.json`。
- 单实例：同一份用户数据目录只许一个应用进程，第二次启动直接退出，由已有的进程聚焦窗口（`main/integration/single-instance.ts`）。用户数据目录显式设置（`integration/user-data.ts`）：正式 `Runyard`，从源码运行 `Runyard-dev`，指定 `--root` 时放在 `<root>/.runyard/app-data`；因此不同 `--root` 的试验窗口与正在用的窗口互不抢锁、互不混数据。
- 关窗口（规格 desktop/workspace「关闭窗口与退出应用」）：macOS 上关窗口只是藏起来，应用和运行继续，点 Dock 图标再显示；其他系统关掉最后一个窗口就退出（`integration/window-lifecycle.ts`）。
- 退出（规格 DESKTOP-WORKSPACE-24）：⌘Q 的第一次退出请求先 `session.bye`（管理进程停掉本连接名下的标签页运行、命令行持有的不动，最多等 5 秒），道别期间的再次请求只拦下，不重复道别也不二次 `app.quit()`；道别 7 秒没回复也照样退出，不让 ⌘Q 失灵。接线在 `quit-coordinator.ts` 的 `registerQuitFlow`，要在窗口生命周期之后登记（决策记录 0005）。连不上管理进程时没有这条流程，退出直接放行。
- 外壳版面：侧栏、顶栏、列表的尺寸只在 `shared/layout.ts` 写一次（留白和胶囊高度取自设计变量），界面把它们写成 `--layout-*`；macOS 用 `hiddenInset` 标题栏，红黄绿画在侧栏顶上（`integration/main-window.ts`）。
- 窗口：`contextIsolation` 开、`sandbox` 开、`nodeIntegration` 关；界面只从 `app://runyard/` 加载打包好的文件（`app-protocol.ts` 只许落在界面目录内），页面带内容安全策略（见下一条）；主进程只响应来自这个地址的 IPC 发送者。
- 内容安全策略（`renderer/index.html`，决策记录 0020，`main/csp.test.ts` 守着）：`default-src 'none'; script-src app://runyard; img-src data:; font-src app://runyard; style-src app://runyard 'unsafe-inline'`。脚本严格（无 `unsafe-eval`、wasm、blob），没有 `worker-src`、`connect-src`；`style-src` 里**不能再加哈希或随机数**（有了它们浏览器忽略 `'unsafe-inline'`，Monaco 的动态 `<style>` 和行样式全被拦）。要放宽任何一条先写决策记录。

- 文件服务（#257，规格 desktop/editor，技术设计 §6.2、§6.4；`main/editor-files/`，类型和白名单在 `shared/editor-files.ts`）：主进程里编辑器的全部磁盘操作（fs-host 的职责），界面经桥的 `files.*` 调用，只传项目 id 加项目内相对路径，绝对路径一律不收；项目文件夹每次从当前列表查（`projectFolder`）。读（文本判定：前 8 KB 无 NUL 且是合法 UTF-8；超过 5 MB 标 `large`，超过 50 MB 不读内容；报告换行符，BOM 原样保留）；写是平台层的 `writeAtomic`（先写同目录临时文件再改名，失败旧文件完好），改名式写入无视只读位，所以先显式检查，只读的文件保存失败；`files.write` 的 `eol` 把换行统一成文件原来的（规格 DESKTOP-EDITOR-30）。新建（排他创建，同名不覆盖）、改名（不覆盖，文件夹用 `moveDir`）、移到废纸篓（只经平台层 `fs.trash`，失败文件留在原处；`unsaved` 先写入再移走，写不进就不移）。服务拿到的平台对象类型里没有 `removeFile`，永久删除在类型上就做不到。路径限制在 `confine.ts`：拒绝 `..`、绝对路径、反斜杠，符号链接带出项目的一律拒绝（含悬空链接和还不存在的目标）；改名、移走处理链接本身。错误是 `EDITOR_*` 代码加参数（`shared/editor-files.ts` 的 `EditorFileErrors`），失败折进结果、不抛给界面；它们的文案随界面 issue（#258、#259）加进 `desktop` 文案包。监听（`change-feed.ts`）：`files.watch` 开启，变化经 `files.changed` 成批推送；根目录下的 `.git`、`.runyard`、`node_modules` 和常见构建产物目录不监听，任意深度的这三个目录名、原子写入的临时文件都不报；自己保存引起的变化标 `self`（保存前登记内容摘要，事件到时读磁盘比对，外部紧接着改成别的内容不会被吞掉）。树里不显示 `.runyard`、`.git`，`node_modules` 照列、点开才读。测试用真实临时目录和假废纸篓（`test-project.ts`），文件名带 `.platform-dependent`；临时目录不删，留给系统清理。

## 打包（#193）

- `pnpm --filter @runyard/desktop package -- --out "$(mktemp -d)"`（入口 `tooling/scripts/package-desktop.ts`，分四步各自打印：esbuild 构建、显式下载 Electron 二进制（`electron:download`，CI 里单独成步）、`pack.ts` 打包并断言开关、`codesign` 校验）；`pack.ts` 把图标同步到 `build/icon.png`，把 `dist/` 拼进临时的应用目录（只有 esbuild 的产物和最小的 `package.json`，依赖已打进单文件，不让打包工具跟随工作区链接），用 electron-builder 26.17.0 出 `.app`、dmg、zip（arm64；`--dir` 只出 `.app`；`--e2e` 保留 `nodeCliInspect`），输出目录不要放在 `/tmp` 下（打包工具把 `/private/tmp` 当不安全路径）；用 `mktemp -d` 的默认位置。输出默认在本包的 `release` 子目录（已忽略），不提交 `.app`、dmg。
- 开关（fuse）取值只在 `packaging/fuses.ts` 写一次（技术设计 §6.5、决策记录 0007）。校验读的是打好的可执行文件里的真实取值（`packaging/verify-fuses.ts`，用 `@electron/fuses`），正式构建断言 `nodeCliInspect` 是关的；出厂的 Electron 反过来是它的反例测试。
- 签名：`mac.identity: "-"`（ad-hoc）加 `resetAdHocDarwinSignature`，打包后 `codesign --verify --deep --strict`，不过就失败。electron-builder 会警告 hardened runtime 与 ad-hoc 签名要 `disable-library-validation`；实测包能正常启动，真机 Gatekeeper 的画面未验证。
- 图标：`build/icon.png` 是 `docs/design/logo/final/png/icon-dock-1024.png` 的副本，`packaging/icon.test.ts` 核对没有脱节；electron-builder 自己转 `.icns`。
- 用户第一次打开的步骤：`docs/guides/first-open-unsigned-app.md`。

## 随包的运行时（#194）

- 打包时 `packaging/runtime-bundle.ts` 用 esbuild 把 `packages/supervisor/src/main-packaged.ts` 和 `packages/cli/src/main-packaged.ts` 各打成单个文件，连同模板数据（`templates/` 的 builtin、runners、tools）、清单 `manifest.json`（`version`、`build` = 版本加随机串、模板数据的 sha256）放进 `Contents/Resources/runyard/`，启动脚本 `packaging/bin/runyard` 放进 `Contents/Resources/bin/`（electron-builder 的 `extraResources`，在 asar 之外：应用的可执行文件要把它们当 Node 脚本直接运行）。模板没有打成压缩包：资源目录本身只读且随应用签名，现成的目录直接给管理进程读；清单里的校验和供以后核对。
- 管理进程和命令行都由应用的可执行文件以 `ELECTRON_RUN_AS_NODE=1` 运行（`runAsNode` 开关必须开，`package` 任务断言）。命令行的版本和构建标识取清单，与应用一致；`runyard doctor` 的 `cli.kind` 是 `app`。
- 应用主进程按 `app.isPackaged` 选 `DesktopRuntime`（`composition-root.ts`）：源码时管理进程入口在仓库里，打包后是 `runyard/supervisor.mjs`；客户端的版本与构建标识也取清单。注意打好的包里 `process.argv` 没有脚本这一项，用户参数用 `userArgv`（`parse-args.ts`）取，不要自己 `slice(2)`。
- 命令行接到 PATH（macOS，技术设计 §5.4）：`integration/cli-link.ts` 在 `~/.local/bin`（可用 `--cli-bin-dir` 指定）建指向 `Contents/Resources/bin/runyard` 的符号链接，只替换或删除指向某个 Runyard 应用启动脚本的链接，别人的 `runyard` 不碰（返回 `conflict`）。入口是应用的 `--install-cli` / `--uninstall-cli` 参数（做完退出，不开窗口，退出码 0，冲突 9）；设置页的按钮随设置页 issue，`~/.local/bin` 是否在 PATH 上也由那时提示。

## 子目录地图
 重命名、备注、自动清理、创建副本（#182，规格 desktop/library-view 34 至 42、desktop/workspace 29）：菜单项和动作在 `renderer/app/use-playground-edits.tsx`（资源库行的 `RowActions` 和运行条的 `RunBarMenu` 共用，“安装或启动中不能改名”的判断也在这里）；重命名和编辑备注的状态是 `use-rename-draft.ts`（名称校验同新建弹窗，回车保存、输入法组词时的回车不算、Esc 取消）。资源库里是行内编辑（`RenameInline.tsx`，`LibraryTable` 经 `DataTable` 的 `editingId` 和 `cellSpan` 让名称框横跨三列），工作区里是小弹窗（`RenameDialog.tsx`，设计稿待 #254）；“自动清理…”是 `AutoCleanDialog.tsx`（设计稿没有这一屏）。主进程一侧是 `main/playground-edits.ts`：`playground.edit`（名称变了才改名，管理进程负责停止、改名、用同一个持有者和端口重新启动；只改备注不碰运行；改名失败时备注也不动）、`playground.autoClean`、`playground.duplicate`，失败原样交回表单，不写全局错误。
- `src/main/`：主进程。`integration/` 放依赖 Electron 的系统差异（窗口外框与底色、单实例、用户数据目录、启动信息），系统分支只许写在这里；`integration/system-actions.ts` 是“在访达中显示”（Electron `shell`）和复制路径（剪贴板）；菜单本身是网页层的 `Menu`，没有原生菜单，`native-ui/` 等第一个原生对话框或通知出现时再建。`index.ts` 只接线；`composition-root.ts` 经 `@runyard/client` 连接或拉起管理进程（客户端种类 `app`）；`library-controller.ts` 是窗口背后的全部逻辑（不认识 Electron，用假客户端测），`console-logs.ts` 是各标签页的控制台数据；`ipc-handlers.ts` 把界面的消息接到控制器；`preview-view.ts`、`integration/main-window.ts` 是 Electron 接线；`app-protocol.ts`、`preview-policy.ts`（含导航判断）是安全相关的纯判断；`smoke.ts` 是冒烟自检。资源库的异常与提示、自动清理的提示（找不到文件夹、智能体创建并运行的提示、提示条、Dock 角标）见 `src/main/AGENTS.md`。 集成终端（#263，规格 desktop/terminal 的后台部分：终端服务、pty-host 进程、node-pty 打包、冒烟）见 `src/main/terminal/AGENTS.md`。 运行条与脚本页的动作（#223、#220、#247，规格 desktop/workspace 25 至 27、31 至 42）：`main/run-bar-actions.ts`（`controller.runBar`）是重启（`run.restart`）、给脚本的输入（`run.stdin`，只在脚本 `running` 时发，加换行）、项目自己的“保存后自动运行”开关（`playground.update`）、清除输出（`logs.clear` 加 `ConsoleLogs.clear`）、预览的刷新、在浏览器中打开（取预览此刻的本机地址）和开发者工具（`PreviewHost.openDevTools`，开在预览页面上）；界面一侧：`RunBar` 的“重启”和命令行持有的说明、`TopBar` 标签上的智能体徽标、`ScriptOutput` 加 `ScriptAutoRun`（全局关时显示为关且不可点）、`ScriptInput`、`ScriptFailure`（脚本没能启动时写原因，输出区只列最后几行）、`PreviewPane` 地址栏的三个按钮、`ConsolePanel` 的“清除”。`TabRow` 多了 `cliOwner`、`stale`、`scriptAutoRun`；脚本 `failed` 时 `failure` 一定有值。
- `src/preload/`：预加载脚本，构建成 CommonJS（沙箱里的预加载脚本不能是 ES 模块）。
- `src/renderer/`：界面，React。`app/`（外壳：`AppFrame` 管文案、`<html>` 属性和版面变量，`AppShell`、`Sidebar`、`TopBar`、`LibraryPage`、`LibraryTable`、`PreviewPane`、`RunBar`、`ScriptOutput`、`ConsolePanel`）、`widgets/`（`PreviewSlot`）、`shared/`（浮层计数器）、`bridge/`（全仓库唯一读 `window.runyard` 的地方，`ui-layers` 守着；别处经 `getDesktopBridge()` 取接口）、`library-view.ts`（列表每一格显示什么的纯判断：状态标记、保留剩余天数、模板缩写、创建者）。CSP 里 `img-src data:` 只为显示主进程截来的预览那一帧；`style-src` 里有一个哈希，放行 Base UI 滚动区插入的固定 `<style>`（见 `index.html` 的注释）。
- `packaging/`、`pack.ts`、`build/`：打包（见上面“打包”）。
- `src/shared/`：主进程、预加载脚本、界面共用的类型和版面常量。

## 测试

纯逻辑用 Vitest 加假客户端（`library-controller.test.ts` 等，测试里不连真管理进程）。Electron 的接线靠 `smoke`，只在本机手动跑：CI 的 Ubuntu 没有显示环境，窗口也不该出现在别人的屏幕上，所以不进 CI。测试和手动试验一律用临时 `--root`，试完用进程号加启动时间确认并结束管理进程。

界面测试（jsdom 文件）共用一份热身：`vitest.setup.tsx` 在每个文件的用例开始前先画一遍外壳并做一次角色查询，再走一遍选择器、新建弹窗、开关和输入，把冷启动的代价（加载、即时编译、jsdom 样式计算）付在装载阶段，不落在该文件第一个用例的时限里（#219、#234、#277）。新增界面测试文件不需要再写自己的热身；不要为此放宽用例的时限。
