Finished icon: the current line

Row 1: before, after (on light grey and on white), and the dark appearance. Row 2: in a mock Dock, using the version where the line stops at the edge. Rows 3 and 4: small sizes, single-colour glyphs, and the small icon next to media player, text-align, notes and terminal icons.
What it shows
Four lines of code: two dark lines have run, one pale line is still waiting, and the orange line is the one being executed. Its leading end is brightest and it crosses the edge of the tile.
Weak point: The sense of motion is moderate; it is still a static bar.
What changed in this pass
The tile went from beige to a clean warm white; five rows became four heavier ones; hollow bars became pale solid bars; the indent went from a wedge to a code-like staircase; the lit line is bright at the front and casts a shadow where it crosses the edge.
Weak point: Without colour the glyph is still close to a generic indent symbol and relies on the heavy bar leaving the edge.
Dock version
Recent macOS fits icons into the system rounded square, so the Dock uses the version where the line is cut exactly at the right edge; the website, README and GitHub avatar use the overshoot version.
Weak point: The Dock picture is a mock-up, not yet checked on a real system; the overshoot is reduced to a cut at the edge.
Dark appearance and small sizes
Dark appearance uses a warm charcoal tile where the lit line is the brightest thing. 32 px is redrawn with four rows and 16 px with three.
Weak point: The dark version belongs to the dark-tile-with-orange-bars family, like OmniOutliner, although only one bar is orange.
