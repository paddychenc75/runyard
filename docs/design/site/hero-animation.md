# 官网顶部动画（#563）

官网首屏右侧的一段网页动画（HTML、CSS，少量 JS），讲一件事：一条命令，代码一行行执行，项目就跑起来了。画面用的是图标的比喻（“正在执行的那一行”冲出边缘，见 `Brand.dc.html`）。静态样子见 `Site.dc.html` 系列画板的首屏，那是动画的最后一帧。

## 舞台里的东西

| 元素 | 内容 | 颜色、阴影 |
| --- | --- | --- |
| 命令胶囊 | `$ runyard new react19 --run` | `color-bg-card`、`shadow-floating`，等宽字 |
| 代码卡 | `react19` 模板真实的 `src/App.tsx`，13 行，带行号 | `color-bg-card`，圆角 28（手机 20），代码配色用 `color-code-*` |
| 执行线 | 6px（手机 5px）的圆头线，在当前行下沿 | 图标渐变 `#E8451A → #FFC94A`（深色 `#EA4A1A → #FFDA6E`），只用在这里 |
| 当前行底色 | 当前行整行 | `color-code-current-line` |
| 预览卡 | 顶部一条：绿点、“运行中”、`127.0.0.1:7104`；下面是 `react19` 页面的**真实截图** | `shadow-overlay`，状态色 `color-status-running-*` |

尺寸：电脑 560×520，代码卡 470 宽；手机 350×400，代码卡 316 宽。

## 关键帧（一轮 6.4 秒，循环）

| 时间 | 动作 | 时长与缓动 |
| --- | --- | --- |
| 0.0–0.4 秒 | 代码卡和命令胶囊淡入（透明度 0→1，向上 8px）；命令按字符打出，约 25 个字符 | 400ms，`motion-easing-standard` `cubic-bezier(0.2, 0, 0, 1)`；打字每字 12ms |
| 0.4–2.4 秒 | 执行线从第 1 行往下走到第 8 行（`<button …>` 那行），每行 250ms。走过的行文字为实色，没走到的行透明度 0.38；执行线所在行加当前行底色。空行（第 2 行）一样占一步 | 每步 250ms 里，前 200ms 位移（`transform: translateY`），后 50ms 停住；`motion-easing-slide` `cubic-bezier(0.32, 0.72, 0, 1)` |
| 2.4–2.9 秒 | 执行线向右伸长，冲出代码卡右边缘 56px（手机 26px），和图标同一个动作 | 500ms，`motion-easing-standard`，只改 `transform: scaleX`（左端为原点） |
| 2.9–3.4 秒 | 预览卡从右侧 24px 外滑入并淡入 | 250ms，`motion-easing-popover` `cubic-bezier(0.34, 1.3, 0.64, 1)` |
| 3.4 秒 | 绿点出现时放大一次（1→1.4→1），只这一次，不循环闪烁 | 300ms |
| 3.4–5.8 秒 | 停住，给人看清楚 | — |
| 5.8–6.4 秒 | 全部淡出到 0，回到第一帧重来 | 600ms，标准缓动 |

只动 `transform` 和 `opacity`，不改布局，不掉帧。时长取自视觉规范第 6 节已有的值（200、250ms 和那三条缓动）。

## 什么时候不动

- 系统开启“减弱动态效果”（`prefers-reduced-motion: reduce`）：不播放，直接显示最后一帧（执行线冲出边缘、预览卡已在、绿点亮着），也没有淡入。
- 舞台不在视野里（`IntersectionObserver`）或标签页在后台（`visibilitychange`）：暂停，回来后从当前一轮的开头继续。
- 第一轮播完前，用户点了首屏的任何按钮：不打断，按钮照常工作。
- 没有 JS：显示最后一帧的静态 HTML（静态页面里本来就是这个样子，JS 只负责把它“倒回去再播”）。

## 无障碍

- 舞台整体 `aria-hidden="true"`，旁边的标题和说明已经讲清楚了；代码文字不让读屏软件逐行念。
- 没有声音，没有闪烁（绿点只放大一次）。
- 浅色、深色跟随页面主题，各用对应的设计变量；预览卡里的截图也换成同主题的那张。

## 要准备的素材

- `react19` 模板跑起来的页面截图，浅色、深色各一张，2 倍清晰度，宽 520px 显示（1040px 原图）。从真实应用的预览里截，不画。
