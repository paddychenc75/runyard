## 规则

- **PRD 说了算。** PRD 和代码不一致时，停下来报告，不要自己选一个。
- **可测试的细节写在规格里，规格不得与 PRD 矛盾。** 规格可以比 PRD 细，两者冲突时 PRD 赢，智能体停下来报告。规格驱动的流程和规格目录随后面的提交加入。
- **不要翻译，不要复述。** 说明文件、代码注释、PR 描述里用引用，不把 PRD 的内容抄一遍。
- **不要擅自改。** 改这个目录里的文件要负责人同意；任务没有明确要求就不动。
- **只引用仓库里有的文件。** 两份文档里提到的调研、讨论、专家报告和评审是负责人的本机归档，不在仓库里，说明文件不能引用它们。

## 怎么引用

- 引用 PRD 用**锚点**，不用章节号：写 `PRD #prd-run-ownership`，或链接 [运行的归属](02-prd.md#prd-run-ownership)。
- 为什么不用章节号：PRD 会加节、删节，编号会移位；移位之后编号照样存在，指向的内容却换了，检查发现不了。
- 锚点是 PRD 里单独一行的 `<a id="prd-…"></a>`，起了名就不改名、不复用；被引用着的锚点不能删。
- 两项检查守着它：`prd-refs`（被引用的锚点存在）、`prd-anchors-kept`（改 PRD 时没有删掉还被引用着的锚点）。
- 技术设计目前还没有锚点，引用它时写文件和章节号，如“技术设计 §8.6.4”。

## 负责人改了 PRD 之后

按锚点在仓库里搜出引用它的说明文件、决策记录和测试，列给负责人，逐个确认是否要跟着改。
