# 0005. 管理进程的单实例、握手和启动方式

状态：已接受

日期：2026-10-12

来源：PRD #prd-run-ownership；技术设计 §2.3、§2.4、§4.2、§5.1、§5.4、§7.1、§7.2 第 4、5 行、§11.1 的 K1

## 背景

决策记录 0002 定下一个共用的管理进程，并把三件事留给技术验证 K1：用 Electron 自己的可执行文件“当作 Node 运行”拉起它行不行；“监听即是锁”能否保证只有一个；Windows 上它能否活过启动者、别人能否冒充或连上它。K1 在负责人的 Mac、`macos-26`、`ubuntu-latest`、`windows-2025`（Windows Server 的 CI 机器，不是真机）上实测。数字、算法和运行链接见 [证据](../evidence/0005-supervisor-singleton-handshake.md)。

## 决定

沿用 0002，不启用“随应用另带独立 Node”的退路；管理进程和命令行保持纯 JS，不加原生模块。补四条：

1. 单实例。Windows 上命名管道本身就是锁。macOS 和 Linux 上，在“连接点就是锁”之外再加一把进程死亡时由内核释放的锁，拿到锁的才许删除残留的 socket 文件并监听：macOS 用 `O_EXLOCK | O_NONBLOCK` 打开 `run/supervisor.lock`，Linux 用抽象命名空间 socket。
2. 握手换成防冒充版本：两个方向的摘要各带不同的固定前缀并都包含两个 nonce，nonce 必须恰好 32 字节；三条消息的形状永不改变，协议版本放在质询和应答里。
3. 启动：`detached`、`windowsHide`、不继承标准输入输出、工作目录设为状态目录、配置只走命令行参数；管理进程启动每个运行都带 `windowsHide`，并去掉子进程环境里的 `ELECTRON_RUN_AS_NODE`。
4. Windows 上启动者把子进程放进“关闭即杀”的 Job Object 时，普通方式启动的管理进程会被带走；改经 WMI 创建可避开（多 0.4 到 1.6 秒）。何时走这条路由真机验证决定。

## 后果

- 实测（440 轮并发启动）有内核锁时 0 次出现第二个管理进程；设计原文的做法在 macOS、Linux 有残留时 20 轮里出现 1 到 18 轮。原文握手能被“空 nonce 加原样回传”骗过（四台机器都复现），新握手 16 种冒充做法 ×4 台机器全被识别，口令一次也没上线。
- 5 秒宽限期、3 秒和 10 秒上限不变：正常退出后最大 166 毫秒停止，强杀后 5.01 到 5.09 秒停止。启动到握手中位数 51 到 78 毫秒（Electron 当 Node），macOS 上没有 Dock 图标，三个系统上都活过应用的退出和强杀（未打包）。
- 锁文件 `~/.runyard/run/supervisor.lock` 进 §4.2；`platform.paths` 检查 socket 路径长度（macOS 104 字节，Linux 108 字节），超了报明确的错误。
- 管理进程被强杀后其子进程可能一直活着，下次启动时按记录核对身份并清理必须做，不能指望它们自己退出（§2.4 已改）。
- 已接受的风险：Windows 命名管道的默认访问控制表允许所有人只读打开，纯 Node 改不了。理由：面向单用户的开发者电脑；口令不在管道上明文传输，发现文件只有本人可读，别人只读打开也走不完握手；修复需要原生模块，会破坏纯 JS 的规则。另：别人先占管道名只会让管理进程起不来，不泄露东西。
- Electron 的 `runAsNode` 开关必须保留（管理进程和内置命令行依赖它）。
- 未验证：从打包后的应用启动（K3，见 0007）；Windows 真机上四种终端各启动后关闭终端、黑窗口的肉眼确认、普通用户下管道的访问控制表、Job Object 的 WMI 创建方式在 Electron 上的做法；注销、休眠；发现文件被删而管理进程活着时无对策。
- 黑窗口项“未验证”，通过标准里这一项在真机上才算数。

## 被否的方案

- 随应用另带独立的 Node：实测没有需要它的理由。
- 只靠“监听失败即退出”做单实例：POSIX 上有残留文件时会出现两个管理进程。
- 锁文件加进程号判断是否过期：判断和抢锁之间有空档，进程号会被复用。
- 给管理进程加原生模块来设置管道访问控制表或创建 Job：破坏纯 JS 规则，而握手已挡住冒充和越权。
