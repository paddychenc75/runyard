# 0023. 区分更新通知的收起和处理

状态：已接受

日期：2026-10-19

来源：PRD #prd-notifications；PRD #prd-settings-items；已批准的 desktop/notifications 与 desktop/settings 规格

## 背景

原更新记录的 `dismissed` 代表用户点过“以后再说”。通知中心要求这项操作只收起卡片，通知继续留在“需要处理”，不能把旧记录中的收起解释成处理完成。

## 决定

在应用数据目录的 `update-check.json` 中增加可选 `handledVersion`，仅当系统成功接受打开下载页的请求后写入对应版本。保留 `dismissed` 的读取及原含义，但它不再抑制待处理通知。旧记录没有新字段时按尚未处理读取。打开浏览器失败时不写处理记录，通知保留，可再次操作。

通知历史仍使用界面自己的 `runyard.notifications.v1` 存储文案键与参数；补充可选的明细和相对时间数据，显示时才按当前语言格式化。主进程的运行、清理和更新状态是判断处理结果的依据，卡片消失不代表处理成功。

## 后果

更新检查继续每天最多一次、不带用户标识、不自动下载。新字段是向后兼容的增量，旧读取方会忽略；不改现有字段含义。清理动作仍走原控制器和移到废纸篓确认，只有实际显示的卡片才回报已提醒。

## 被否的方案

- 把旧 `dismissed` 当处理完成：会错误吞掉用户过去只是收起的通知。
- 点按钮立即删除通知：浏览器打开或清理失败时会丢失仍需处理的事项。
- 持久保存已翻译文字：切换语言后历史通知会保留旧语言。
