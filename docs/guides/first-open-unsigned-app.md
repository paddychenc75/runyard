# 首次打开未签名的应用

第一版的 macOS 安装包没有签名也没有公证（技术设计 §10，决策记录 0007），系统会拦下第一次打开。这份手册把用户要走的步骤原样写出来，README 和下载页链到这里。

## 何时用

- 把 `Runyard-<版本>-mac-arm64.dmg` 或 `.zip` 交给别人、写下载页或回答“打不开”的问题时。
- 自己在新机器上第一次试装时。

## 步骤

1. 打开 dmg，把 Runyard 拖进“应用程序”文件夹（或解压 zip，同样把应用放进“应用程序”）。**先拖进去再打开**：带隔离标记的应用如果在“下载”文件夹或磁盘映像里直接打开，系统会把它换到一个随机的只读路径运行，`runyard://` 链接不会交给它（K3 实测）。
2. 双击 Runyard。系统弹窗说无法验证开发者，没有“仍要打开”按钮；点“完成”。
3. 打开“系统设置 → 隐私与安全性”，往下滚到“安全性”，点“仍要打开”，再确认并输入登录密码。之后再双击就能正常打开。
4. 懂命令行的可以一步做完：`xattr -dr com.apple.quarantine /Applications/Runyard.app`。
5. 每次更新都要重做：浏览器下载的文件都会带隔离标记。应用内只提示有新版本、不会自动更新（macOS 的自动更新要求已签名）。

说明：

- 弹窗里有哪些按钮、“按住 Control 点击打开”的旧捷径从 macOS 15 起已取消，这两点来自第三方，**没有在真机上核实**；系统设置这条路径来自 Apple 支持页面。
- 应用没有系统通知（未签名发不出）；提示显示在应用里。
- 项目默认放在 `~/Runyard`，不在“桌面、文稿、下载”这些受保护的文件夹里；把项目放进这些文件夹，系统会问一次访问授权，更新后可能要重新给（未验证）。
- 安装包随附 `SHA256SUMS.txt`，可以核对下载是否完整；它不影响系统的拦截。

## 验证

- 照步骤 1 到 3 在一台没有装过的 Mac 上走一遍，应用能开窗。
- 本机做出的包：`codesign --verify --deep --strict /Applications/Runyard.app` 没有输出、退出码 0（包是 ad-hoc 签名，不是“已签名”；没有它在 Apple 芯片上会显示“已损坏”）。
