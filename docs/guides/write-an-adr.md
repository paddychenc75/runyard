# 写决策记录（ADR）

## 何时用

出现下面任何一种情况，在同一个 PR 里写一份决策记录：

- 增删一个包，或改了 `tooling/checks/layers.json` 里的依赖规则
- 给应用或命令行加运行时依赖；Electron、Vite、TypeScript、pnpm 升大版本
- 协议出现不兼容的改动；磁盘上的格式有改动
- 构建、发布、安全做法有改动
- 技术验证得出了结论
- 要推翻以前的某份记录

负责人看中文的产品文档做决定；决定之后由智能体写成一份记录。记录只写结论和后果，不重复论证过程。技术验证的记录例外：实测的数字、算法的伪代码、环境和证据链接太长，放不进 60 行，写在 `docs/architecture/evidence/` 里与记录同编号同名的文件，记录用链接指过去（现有的 0005 到 0011）。证据文件只记已经得出的事实，不记讨论过程。

## 步骤

1. 看 `docs/architecture/decisions/` 里已有的记录，取下一个编号（最大编号加一，四位数字，不跳号、不复用）。
2. 新建文件 `docs/architecture/decisions/NNNN-kebab-case-title.md`，文件名用小写英文和连字符。
3. 按下面的模板写，中文，不超过 60 行：

   ```markdown
   # NNNN. 标题

   状态：提议中

   日期：YYYY-MM-DD

   来源：PRD #prd-run-ownership；技术设计 §2.3

   ## 背景

   当时面对什么问题。

   ## 决定

   决定了什么，一段话。

   ## 后果

   因此必须做什么、不能做什么。

   ## 被否的方案

   每个被否的方案一行，写明原因。
   ```

4. “状态”只能写三种：`提议中`、`已接受`、`已被 NNNN 取代`。负责人同意之后才写 `已接受`。
5. “来源”写这个决定出自哪里：PRD 用锚点，技术设计写章节号。只引用仓库里有的文件。
6. 内容必须来自产品文档或负责人的决定，不要自己补理由。没有出处的地方停下来问。
7. 要改变一份已接受的记录：不改它的正文。新写一份，再把旧记录的“状态”一行改成 `已被 NNNN 取代`。
8. 这个决定如果改变了根 `AGENTS.md` 或 `docs/architecture/overview.md` 里写着的规则，同一个 PR 里改掉。

## 验证

运行 `pnpm check`。相关的几项：

- `adr-index`：文件名、编号连续、第一行、状态、日期、来源、四个章节
- `docs-size`：不超过 60 行
- `docs-links`、`prd-refs`：链接和 PRD 锚点都存在

## 完成标准

- `pnpm check` 通过。
- 记录能让一个没参加讨论的人看懂：当时的问题、定了什么、之后受什么约束。
- 状态是 `已接受` 的，负责人确实同意过。
